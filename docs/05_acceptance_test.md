## 四、观察与已知限制

1. **检索跨病种噪声（已缓解）**：根因是 `similarity_threshold=0` + 纯向量召回时各指南相似度高度重叠（实测相关 0.832–0.907、不相关 0.829–0.890），**提高阈值无法区分**，会同时砍掉正确证据，故不采用阈值方案。改为把 Retrieval 的 `keywords_similarity_weight` 由 0 调到 **0.3**（vector=0.7）；源码确认 `keywords_similarity_weight ≥ 0.01` 即启用混合检索（`internal/agent/tool/retrieval_nlp.go` 中 `vectorOnly := req.KeywordsSimilarityWeight != nil && *req.KeywordsSimilarityWeight < 0.01`）。继续升到 0.5 会把英文 ELN 指南挤出（R04 失去 ELN 证据），故取 0.3。
   - 效果（同一批 25 条、`top_n=8`、kw=0.3）：同病种 chunk 150/200，`keywords_similarity_weight=0` 时为 123/200（历史测量），期望来源 chunk 141/200；
   - `top_n` 8→12（2026-11-12 14:33）：每条召回 12 chunks，期望来源 198/300、同病种 206/300，且 R11 转为实质作答。
2. **KG 不返回指南原文**：`evidence_types.guideline_text` 恒为 `false`，指南证据统一由 Retrieval 节点提供。
3. **引用格式（2026-11-12 调整）**：API 返回 `[ID:<chunk_id>]`。最终分析 Agent 的 `cite` 由 `true` 改为 `false`：`cite=true` 时 RAGFlow 会在系统提示后追加内置引用助手提示（容器二进制原文：`Based on the provided document or chat history, add citations to the input text… # Citation Requirements: … DO NOT modify whitespace or original text`），模型因此把任务当成“给原文补标引用”，输出「您的文本整体严谨…最小必要修改」式元叙述，R10 甚至只输出第 1 段。关闭后回答直接以 `### 1) 结论` 开头、三段齐全；代价是 UI 不再生成 `[1]…[n]` 编号卡片（原始 chunk ID 仍保留在正文，可回溯）。2026-11-12 17:14 恢复配置重跑后，25 条全部使用 `[ID:<chunk_id>]` 方括号格式（`sum25.py` 统计 `zero_ids` 为空，R07 为 6 个 `[ID:]`），此前 R07 的格式瑕疵不再出现。
4. **登录口令口径**：见 `docs/04_ragflow_integration.md` 第 4 节（前后端 base64 不一致的处理）。
5. **弃答 3 条（证据优先，非故障）**：2026-11-18 批次 R07（APL 分化综合征处理）、R18（CML 加速/急变期治疗）、R19（CLL 一线治疗）在检索到的 12 个 chunk 中缺少可直接回答问题的方案段落，最终 Agent 按系统提示写「无法依据现有指南原文…」并列出缺口；R03、R14 为部分作答（先答可支持部分并单列证据缺口）。11-17 批次仅 R14 弃答，两批次差异来自生成端随机性与证据充分性判断，属证据优先规则下的正常波动，不是模型故障。历史核查（11-12）：R07 的 12 个 chunk 中「分化综合征/维甲酸综合征/ATRA综合征」出现 0 次；R18 只检索到「（六）进展期患者的治疗」标题及其后的急变期诊断标准，无 AP/BP 治疗方案；R03 虽有「移植」泛述但无适应证人群；R19 指南章节未含一线方案推荐。
6. **检索召回不足（部分解决）**：知识库 10 篇文档仅 384 chunks，部分指南治疗章节被切成大块且开头措辞与问题不相似，向量排序偏低。实测：R11 需要的 `7a7e87f677742f1c`（含长春新碱/柔红霉素/泼尼松/门冬酰胺酶）在 `top_n=8` 时排第 11、召回不到，调至 12 后已命中；R03 需要的 `77e7707abde6b1a9` 在 top 12 之外；CLL 指南的治疗 chunk `9c75306a51d28c98` / `2a0829e4047b2f04` 在 top 30 之外（`top_n=8` 时期探测）。进一步改进方向：把 `top_n` 提到 20、或改进入库分块（按章节/表格切分）。
7. **图谱路径口径**：2026-11-17 批次仅 R04 明确写「图谱未提供可用路径」，其余 24 条在第二段引用/列出图谱分类关系或注明其不支撑结论。实际 `paths` 为 5–11 条：多数为 `SUBTYPE_OF` 分类边，R06–R09 还返回 `TREATS`、R20 返回 `ASSOCIATED_WITH`，但模型判定这些关联不覆盖问题所需的治疗方案/机制，故按提示声明“无可用路径”或不以其作为结论依据。这与第十四章「不允许仅凭图谱边生成诊疗结论」一致；R20 还主动指出图谱中 CLL→ALL 的分类边在医学上存疑。
8. **RAGFlow 前端自动保存会覆盖 API 改动**：画布会把浏览器内存中的旧 DSL 整体写回服务端；当页面在 API 修改前打开、或该 origin 留有旧缓存时，`sys_prompt`/`cite` 会被回退。改完 DSL 后应关闭该 origin 的所有画布页面、重新登录/刷新，并用 API 复核 `Agent:KhakiPoetsSend.params` 的 `cite=false`、`sys_prompt` 787 字；当前线上配置已按此复核（2026-11-19 回滚后 `update_time=1795055089414`，内容仍为 787 字）。
9. **与第十四章流程图的拓扑偏差（有意为之，需知悉）**：第十四章示意图在「查询规划 Agent」与「检索词生成 Agent」之间有「患者数据查询 / 患者事实整理」节点；本 V1 没有患者库/病历数据源，且第一章明确患者数据不进入知识图谱，因此画布为 Begin→查询规划 Agent→检索词生成 Agent，未设该节点。两路证据（Retrieval ∥ KG API）→最终 Agent 的结构未变；后续接入患者库时再补，不以占位节点冒充。
10. **引用格式偶发短 ID**：最终回答的 `[ID:…]` 由 LLM 生成，偶发截断或拼接。2026-11-19 复跑时 R05 前两次出现 `[ID:3]`，被 citation 校验判 FAIL，第 3 次通过；同一轮尝试在提示词中硬约束 16 位 ID 后，R05 通过但 R15 在“依据的图谱路径”段生成 24 位拼接 ID，故已回滚到 787 字提示词。验收规则：citation 校验失败时同一问题最多重试 2 次，仍失败才判 FAIL；短 ID 只按格式问题处理，不解释为图谱或检索错误。
